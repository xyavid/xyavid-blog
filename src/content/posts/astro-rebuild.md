上一个博客是四年前用现成主题搭的，配置项改了三十多处，最后还是有一半功能从来没用过。这次重建，第一条原则就是：不引入用不到的东西。

## 选型的约束条件

我的需求很具体：写文章、展示项目、按分类和标签归档。没有公式，没有多语言，不需要评论和后台。

这样一来，很多流行方案其实都不合适。带后台的 CMS 要维护服务器，主题型框架会把项目展示这种非标准内容类型变成硬仗。最后选的是 Astro，用内容集合（Content Collections）自己定义数据结构，不套现成主题。

## 内容即数据

文章和项目各是一个集合，字段由 schema 约束。写错字段名或者漏了日期，构建阶段就会直接报错，而不是等到线上才发现某个页面空了。

```ts
const posts = defineCollection({
  loader: glob({ base: "./src/content/posts", pattern: "**/*.md" }),
  schema: ({ image }) =>
    z.object({
      title: z.string(),
      pubDate: z.coerce.date(),
      category: z.enum(CATEGORIES),
      tags: z.array(z.string()).default([]),
    }),
});
```

分类用固定枚举而不是自由字符串，是故意的。自由字符串写久了必然出现「前端」「前端开发」「Frontend」三种写法，归档页会碎成一片。

## 被否掉的方案

**套现成主题。** 观感确实开箱即用，但那些主题普遍带着看板娘、音乐播放器、动态背景这类和写作无关的东西。做减法的成本，比从零写布局还高。

**客户端渲染的框架。** 博客是纯静态内容，为此加载一整套运行时并不划算。Astro 默认输出零 JavaScript，只有搜索和主题切换需要一点点脚本。

**把内容放在数据库里。** 个人站的内容量级在几百篇以内，Markdown 文件加 Git 就是最好的版本管理，还能随时整体搬走。

## 结果

整个站点构建后是纯静态文件，可以直接丢到任何静态托管上。加一篇新文章只需要在目录里新建一个 Markdown 文件，其余页面、归档、标签、RSS 全部自动更新。
